# ContractBoard

Paper(1.20系以降)向けの依頼掲示板プラグイン。プレイヤー同士が報酬付きの「依頼」を出し合える仕組みをチェストGUIで提供する。

## 特徴

- `/irai` コマンドでどこからでもチェストGUIの依頼所を開ける
- 依頼作成・一覧閲覧・受注・完了承認・評価をGUI上で完結
- 報酬はVault経由の経済プラグイン通貨のみ(アイテム報酬なし)
- 依頼ごとに「アイテム納品あり/なし」を選べる。ありの依頼には専用の**納品ボックス**(チェスト1個分・27スロット)が付き、受注者が成果物を入れ、依頼者が完了承認した時点で依頼者の**保管庫**へ移る
- 納品ボックスの中身は納品報告した瞬間に固定され、受注者は出し入れできなくなる。依頼者は報告前から中身を閲覧できる(取り出しは不可)
- 納品内容が不十分な場合、依頼者は「やり直しを依頼」で差し戻せる(受注中へ戻り、自動承認の待ち時間もやり直しになる)
- ギブアップ・強制差し戻し・運営による強制終了では、納品ボックスの中身が受注者の保管庫へ戻る(アイテムが消えない)
- 確定したアイテムは `/irai vault` の保管庫に入り、本人がGUIから受け取る(足元へのドロップはしない)。相手がオフラインでも受け渡しは成立し、オフライン中に発生した通知は次回ログイン時にまとめて届く
- 依頼作成時に報酬へ手数料を上乗せ徴収し、依頼所に一時的にエスクロー
- 依頼者がGUI上で完了承認を選ぶと星1〜5の評価画面が開き、評価を選択して初めて受注者への報酬支払いと依頼完了が成立する(評価なしで完了する抜け道なし、依頼者→受注者の一方向)
- 依頼者は依頼作成時に「受注に必要な最低星数」を任意で設定でき、平均評価が満たない受注者は受注できない(評価実績がない初回受注者は対象外、条件未達は一覧・詳細画面にも表示)
- 期限切れの依頼は自動失効し、報酬(手数料分を除く)を依頼者へ自動返還
- 受注者は「納品完了を報告」でき、報告後に依頼者が一定時間放置した場合は自動的に承認され報酬が支払われる(依頼者の放置による未払いを防止)
- 受注者が受注したまま放置した場合、一定時間後に依頼者が受注を強制的に取り消して募集中へ戻せる(受注者の放置による依頼の塩漬けを防止)
- 完了・取り下げ・期限切れになった依頼は保持期間(既定30日)を過ぎると自動的にデータベースから削除される
- SQLiteによる永続化(単一ファイル、サーバー再起動後もデータを保持)
- 新規依頼の作成時に `ContractCreatedEvent` を発火する。Discord通知など外部連携はこれを購読して行う

## 動作要件

- Paper 1.20系以降
- Vault、および対応する経済プラグイン(EssentialsX等)
- Java 17以上(Paper 26.1系以降はJava 25)

## コマンド

| コマンド | 説明 |
| --- | --- |
| `/irai` | 依頼所のメインメニューを開く |
| `/irai create` | 依頼作成を開始する(チャット入力形式、入力内容は全体チャットに流れない) |
| `/irai list` | 募集中の依頼一覧を開く |
| `/irai my` | 自分の依頼を確認する |
| `/irai vault` | 保管庫(受け取り待ちのアイテム)を開く |
| `/irai cancel` | 進行中の依頼作成入力をキャンセルする |
| `/irai admin cancel <依頼ID>` | (`irai.admin`権限)依頼を強制終了し、報酬を依頼者へ、納品ボックスの中身を受注者へ返す |

## GUI操作

`/irai` で開くチェストGUIだけで、依頼の作成開始・閲覧・受注・納品ボックスへの出し入れ・納品報告・完了承認・評価・保管庫からの受け取りまで一通りの操作ができる。サブコマンドはGUIの各画面へのショートカットで、GUIからできずコマンドが必要なのは `/irai cancel`(依頼作成のチャット入力の中断)と `/irai admin cancel`(運営操作)だけ。

GUI内のアイテムは取り出せない(クリックはすべてキャンセルされる)。**唯一の例外が納品ボックス**で、受注中の受注者本人が開いたときだけチェストと同じように出し入れできる。

### チャット入力形式(依頼作成)について

依頼作成のタイトル・詳細説明・報酬額・期限・最低星数・アイテム納品の有無の入力は、通常のチャットではなくBukkitの会話(Conversation)モードで受け取る。この間の入力は依頼所だけが受け取り、全体チャットやDiscord連携先には流れない。`request.input-timeout-seconds`(既定120秒)を超えて入力がない場合は自動的にキャンセルされる。

### メインメニュー(`/irai`)

| アイテム | 操作 |
| --- | --- |
| 本「依頼を探す」 | 募集中の依頼一覧を開く(`/irai list` と同じ) |
| 羽根「依頼を作成する」 | GUIを閉じ、チャット入力による依頼作成を開始する(`/irai create` と同じ) |
| 名札「自分の依頼」 | 出した依頼・受けた依頼の一覧を開く(`/irai my` と同じ) |
| チェスト「保管庫」 | 受け取り待ちのアイテムを開く(`/irai vault` と同じ) |

### 依頼一覧

- 募集中の依頼を1ページ45件まで紙アイテムで表示し、依頼者・報酬・期限・アイテム納品の有無・受注条件・詳細説明の冒頭30文字を表示する
- 依頼をクリックすると詳細画面を開く
- 自分の平均評価が受注条件(最低星数)に届かない依頼は、タイトルが暗い灰色、受注条件の行が赤で表示される
- 矢印で前後のページへ移動、バリアでメインメニューへ戻る
- 募集中の依頼が1件もない場合はチャットにその旨が表示される

### 依頼の詳細

- 中央のアイテムに依頼者・報酬・期限・状態・納品方法・受注条件・受注者・詳細説明の全文を表示する
- アイテム納品ありの進行中の依頼では、当事者(依頼者・受注者)にチェスト「納品ボックスを開く」が表示される
- 募集中かつ自分の依頼でなければ、緑の羊毛「この依頼を受注する」で受注できる(受注すると自動でメインメニューへ戻る)
- 受注条件を満たしていない場合は代わりに赤い羊毛「受注条件を満たしていません」が表示され、クリックしても受注できない
- 矢印で直前の画面(一覧またはメインメニュー)へ戻る

### 自分の依頼

上段に「自分が出した依頼」、続けて「自分が受注した依頼」を並べる(表示は合計44スロットまで)。状態に応じて次の操作ボタンが出る。

| 表示 | 対象 | 操作 |
| --- | --- | --- |
| 緑の染料「クリックで完了承認(星評価が必須です)」 | 自分が出した依頼のうち受注中・納品報告済みのもの | 評価画面を開く(星を選ぶまで完了しない) |
| 赤の染料「クリックで取り下げ」 | 自分が出した募集中の依頼 | 依頼を取り下げ、報酬分を返還する(手数料分は戻らない) |
| 緑の染料「クリックで納品完了を報告」 | 自分が受注中の依頼 | 依頼者へ納品完了を通知し、自動承認の待ち時間を開始する |
| 黄の染料「クリックで受注を取り消す(ギブアップ)」 | 自分が受注中の依頼 | 受注を取り消して依頼を募集中へ戻す(ペナルティなし) |
| 赤の染料「放置されています / クリックで強制的に募集中へ差し戻す」 | 自分が出した依頼のうち、受注から `request.auto-approve-hours` を過ぎても納品報告がないもの | 受注を取り消して募集中へ戻す(条件を満たしたときだけ追加表示される) |
| 橙の染料「クリックでやり直しを依頼(差し戻し)」 | 自分が出した依頼のうち納品報告済みのもの | 納品ボックスのロックを解除して受注中へ戻し、自動承認の待ち時間をリセットする(回数制限なし) |
| チェスト「クリックで納品ボックスを開く」 | 自分が受注中の、アイテム納品ありの依頼 | 納品ボックスを開いて出し入れする |
| チェスト「クリックで納品ボックスの中身を確認」 | 当事者から見た、アイテム納品ありの進行中の依頼 | 中身を閲覧する(取り出し不可) |

完了・取り下げ・期限切れなど操作対象外の依頼は「(操作なし)」と表示され、クリックしても何も起きない。

### 納品ボックス

- アイテム納品ありの依頼にだけ付く、依頼専用のチェスト1個分(27スロット)の受け渡し場所
- ボタンや飾りを一切置かないため、誤って飾りを持ち出す事故が起きない
- **受注中の受注者本人が開いたときだけ**、ドラッグ・シフトクリックを含めチェストと同じ操作で出し入れできる
- 中身はスロットが変わるたびにSQLiteへ書き込まれる。GUIを開いたままサーバーが落ちてもアイテムは失われない
- `box.banned-materials` に指定したアイテムは入れられず、入れようとすると手元へ戻る(手持ちが一杯なら保管庫へ)
- アイテム納品ありの依頼では、ボックスが空のままでは納品報告できない
- 依頼者は報告前から中身を閲覧できるが、この画面から取り出すことはできない

アイテムの行き先は次の通り。いずれの経路でもアイテムは消えず、必ずどちらかの保管庫に入る。

| きっかけ | 報酬(通貨) | 納品ボックスの中身 |
| --- | --- | --- |
| 依頼者が完了承認(星評価) | 受注者へ | 依頼者の保管庫へ |
| 自動承認(納品報告後の放置) | 受注者へ | 依頼者の保管庫へ |
| 依頼者が差し戻し | 動かない | ボックスに残る(ロック解除) |
| 受注者がギブアップ | 依頼所に据え置き | 受注者の保管庫へ |
| 依頼者が強制差し戻し(受注者の放置) | 依頼所に据え置き | 受注者の保管庫へ |
| 期限切れ・依頼者の取り下げ | 依頼者へ返還(手数料除く) | (募集中のため中身なし) |
| `/irai admin cancel` | 依頼者へ返還 | 受注者の保管庫へ |

### 保管庫(`/irai vault`)

- 完了承認・返却で確定したアイテムを、プラグインが本人に代わって預かる場所
- アイテムをクリックすると受け取る。インベントリに空きがない場合は受け取れなかった分が保管庫に残る(足元へのドロップはしない)
- 各アイテムには預かった理由・預かり日時・保管期限が表示される
- `box.vault-slots`(既定27)を超えて溜まると取り出しを促す警告が出る。ただし**承認や返却そのものは止めない**ので、依頼が保管庫の満杯で詰まることはない
- `box.vault-retention-days`(既定30日)を過ぎたアイテムは削除される。予告なしに消えないよう、`box.vault-warn-days-before`(既定3日前)と `box.vault-final-warn-days-before`(既定1日前)にログイン時通知が出る

### オフライン時の動作

受け渡しはすべてプラグインが預かるため、相手がログインしていなくても成立する。オフライン中に発生した通知(納品報告・完了承認・差し戻し・返却・保管期限の警告など)はデータベースに溜まり、次回ログイン時にまとめて届く。

### 評価

- 「完了承認」を選んだときだけ開く画面で、★1〜★5の染料が並ぶ
- 星をクリックした時点で依頼が完了し、受注者へ報酬が支払われ、評価が記録される
- 星を選ばずに画面を閉じた場合は完了も支払いも行われない(評価なしで完了する抜け道はない)
- コメント入力欄はなく、記録されるのは星数のみ

| 権限 | 説明 | デフォルト |
| --- | --- | --- |
| `irai.use` | 依頼掲示板の利用(作成・受注・評価・納品ボックス・保管庫) | true(全員) |
| `irai.admin` | 依頼の強制終了(`/irai admin cancel`) | op |

## ビルド方法

```bash
mvn package
```

`target/contractboard-1.0.0.jar` が生成されるので、サーバーの `plugins` フォルダに配置する。

## Dockerでの簡易テスト

Docker daemon が起動している状態で、次のスクリプトを実行すると Paper 26.1.2 のテストサーバーを Java 25 で起動し、ContractBoard・Vault・EssentialsX の読み込み、`/irai` のプレイヤー専用チェック、SQLite テーブル作成を確認できる。

```bash
MC_RCON_PASSWORD="$(openssl rand -hex 16)" ./scripts/test-plugin.sh
```

`MC_RCON_PASSWORD` は `compose.yaml` が必須にしている環境変数で、未設定だと `docker compose` が起動前に停止する。

サーバーは `25565` 番ポートで起動したままになり、データは `server-data-26.1.2/` に保存される。停止する場合は次を実行する。

```bash
docker compose down
```

## 設定 (`config.yml`)

- `request.min-reward` / `request.max-reward`: 報酬額の下限・上限
- `request.min-expire-hours` / `request.max-expire-hours`: 依頼の期限(時間)の下限・上限
- `request.max-title-length` / `request.max-description-length`: タイトル・詳細説明の最大文字数
- `request.min-stars-max`: 依頼作成時に設定できる「受注に必要な最低星数」の上限(0〜この値、0は条件なし)
- `box.banned-materials`: 納品ボックス・保管庫に入れられないアイテム(Material名の一覧、既定は制限なし)
- `box.vault-slots`: 保管庫にこの件数を超えて溜まったら取り出しを促す警告を出す(既定27、0以下で無効化)
- `box.vault-retention-days`: 保管庫のアイテムを預かってから何日で削除するか(既定30日、0以下で無期限保管)
- `box.vault-warn-days-before` / `box.vault-final-warn-days-before`: 削除の何日前に一次警告・最終警告を出すか(既定3日前・1日前)
- `request.fee-rate`: 依頼作成時に報酬へ上乗せする手数料率(徴収分は消滅し、取り下げ・期限切れでも返還されない)
- `request.auto-approve-hours`: 受注済み・納品報告済みの依頼が放置された場合の猶予時間(時間単位)。納品報告後にこれを超えると自動承認、受注後(納品報告なし)にこれを超えると依頼者が強制的に受注を取り消せる
- `request.reminder-hours-before`: 上記の何時間前に当事者へ事前リマインドを送るか
- `request.retention-days`: 完了・取り下げ・期限切れになった依頼を保持する日数(既定30日、0以下で無効化)
- `request.input-timeout-seconds`: 依頼作成のチャット入力(会話モード)を何秒放置したら自動キャンセルするか(既定120秒)
- `expiration-check-interval-seconds`: 期限切れチェック・放置依頼チェックの実行間隔(秒)
- `messages`: 各種メッセージ文言(日本語固定)

## 使い方の流れ

1. 依頼者が `/irai create` でタイトル・詳細説明・報酬額・期限・受注に必要な最低星数をチャット入力し、依頼を作成する(報酬+手数料が徴収され、報酬分は依頼所に預けられる)
2. 受注者が `/irai list` から依頼を選んで受注する(同時受注は1人1件まで、受注後のキャンセルはペナルティなし)
3. 依頼者がGUI上で完了承認を選ぶと星評価画面が開き、評価(1〜5)を選択すると受注者へ報酬が支払われ依頼が完了する
4. 期限切れになった依頼は自動的に失効し、報酬分が依頼者へ返還される
5. 受注者は作業完了時に「納品完了を報告」でき、報告後に依頼者が`request.auto-approve-hours`で設定した時間放置すると自動的に承認・支払いが行われる
6. 受注者が納品報告もギブアップもせず`request.auto-approve-hours`で設定した時間放置した場合、依頼者は受注を強制的に取り消して募集中に戻せる

## 対象外の機能

- NPCや専用設置ブロックとの連携
- アイテム報酬・アイテム納品の自動判定
- 受注者から依頼者への評価
- 権限プラグインによる細かい作成・受注制限
- MySQL対応、BungeeCord/Velocity構成での複数サーバー連携

詳細な仕様の背景は [AGREEMENT.md](AGREEMENT.md) を参照。
